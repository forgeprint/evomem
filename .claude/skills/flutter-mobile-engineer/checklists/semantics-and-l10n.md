# Semantics and localisation

Flutter draws its own pixels, so the platform screen reader sees only what the
semantics tree says. Much of that tree can be checked in a widget test, which
turns an accessibility first pass into something CI runs. This is not a
conformance audit.

| #    | Check                                                                                                  | How                                                                                    | Source                                                  |
| ---- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| SL1  | Widget tests assert `labeledTapTargetGuideline` on every screen                                        | `grep -rn "labeledTapTargetGuideline" test`                                            | Flutter 3.47 — accessibility testing; WCAG 2.2 SC 4.1.2 |
| SL2  | Widget tests assert `androidTapTargetGuideline` (48 by 48) and `iOSTapTargetGuideline` (44 by 44)      | `grep -rnE "(android\|iOS)TapTargetGuideline" test`                                    | Flutter 3.47 — accessibility testing; WCAG 2.2 SC 2.5.8 |
| SL3  | Widget tests assert `textContrastGuideline`, and the report says what it cannot see (text over images) | `grep -rn "textContrastGuideline" test`                                                | Flutter 3.47 — accessibility testing; WCAG 2.2 SC 1.4.3 |
| SL4  | Every `IconButton` has a `tooltip` or sits in a `Semantics(label:)`                                    | `grep -rn -A4 "IconButton(" lib \| grep -c tooltip` against the count of `IconButton(` | Flutter 3.47 — `Semantics` API; WCAG 2.2 SC 1.1.1       |
| SL5  | Decorative images are excluded: `excludeFromSemantics: true` or `ExcludeSemantics`                     | read each `Image` and `SvgPicture` that carries no meaning                             | Flutter 3.47 — `Semantics` API; WCAG 2.2 SC 1.1.1       |
| SL6  | No `TextScaler.noScaling` or fixed `textScaleFactor` on body text; caps use `withClampedTextScaling`   | `grep -rnE "TextScaler\.noScaling\|textScaleFactor:" lib`                              | WCAG2Mobile — 1.4.4; WCAG 2.2 SC 1.4.4                  |
| SL7  | Screens are checked at the largest system text size without clipped text                               | a widget test with a large `textScaler`, or a device pass                              | WCAG2Mobile — 1.4.4                                     |
| SL8  | User-facing strings come from `AppLocalizations`, generated by `flutter gen-l10n` from ARB files       | `l10n.yaml` exists; `grep -rnE "Text\(\s*'" lib` returns only non-user-facing strings  | Flutter 3.47 — internationalization                     |
| SL9  | `localizationsDelegates` include `AppLocalizations.delegate` and the global Material delegates         | read `MaterialApp`                                                                     | Flutter 3.47 — internationalization                     |
| SL10 | Changed flows were walked with TalkBack and VoiceOver, or the report says they were not                | the report's "not checked" section                                                     | Flutter 3.47 — accessibility testing                    |

## Commands

```dart
testWidgets('meets the tap target and label guidelines', (tester) async {
  final handle = tester.ensureSemantics();
  await tester.pumpWidget(const App());
  await expectLater(tester, meetsGuideline(androidTapTargetGuideline));
  await expectLater(tester, meetsGuideline(iOSTapTargetGuideline));
  await expectLater(tester, meetsGuideline(labeledTapTargetGuideline));
  await expectLater(tester, meetsGuideline(textContrastGuideline));
  handle.dispose();
});
```

## Why each one

**SL1–SL3** are the reason this checklist exists for Flutter specifically: the
framework ships guideline matchers, so an unlabelled button fails a test rather
than waiting for somebody with a screen reader to find it.

**SL6** because `TextScaler.noScaling` fixes a layout that breaks at large text
by ignoring the setting the user needs.

**SL8** because a string literal in a `Text` is a string no translator will
ever see, and it is found by grep in seconds.
